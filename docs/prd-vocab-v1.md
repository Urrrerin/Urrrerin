## 2. 产品目标

### 2.1 一句话

私人用的哈利波特阅读生词词典：**能查，更能按间隔重复把旧词反复拎出来复习，并保证学习进度不丢。**

### 2.2 每日学习结构（V1.0 核心）

旧词不是「学一遍就过」。每个已学词按间隔重复（艾宾浩斯/SM-2 一类）在到期日再次出现。

**每天打开 Quill 的默认顺序：**

1. **先复习**到期旧词：目标约 **50～75** 个（若到期不足则有多少刷多少；若远超则可设上限，默认建议 75）  
2. **再新学**当日新词：默认 **30** 个  

未完成的复习应优先于新学；不要先刷完 30 个新词再复习。

### 2.3 V1.0 成功标准

- 每日按「先复习 → 再新学」跑通  
- 复习用三档反馈，并据此安排下次出现时间  
- 杀进程、隔天再开，进度仍在  
- 词库扩容发版后，旧词进度仍在，新词可进入新学池  
- 仅在本人 iPhone 上使用即可  

### 2.4 本阶段不讨论

私人工具范围之外的话题（账号、分发上架、社交等）不写入后续迭代，除非你主动提起。

## 4. 核心概念与硬约束

| 概念 | 含义 | 约束 |
| --- | --- | --- |
| WordEntry | 词条内容（词、音标、释义、标签、频次、章节…） | 来自轨道 A，可更新 |
| LearningState | 学习进度（是否学过、熟悉度、下次复习时间等） | **不能丢** |
| 今日队列 | 当日复习列表 + 新学列表 | 每日按规则生成 |

### 4.1 「进度不能丢」意味着什么（产品要求）

1. **词库发版/刷新不得覆盖或重置 LearningState**  
2. **常规使用**（杀 App、锁屏、隔天打开）进度必须还在  
3. 针对 iPhone Safari / 主屏幕 PWA 清缓存会丢本地数据的风险：V1.0 必须提供 **学习进度导出 + 导入**（如 JSON 文件），作为进度安全网；后续可再加强（如定期提醒备份）  
4. 词条对齐键必须稳定（冻结 `id` 规则，并以规范化英文词形为辅键），避免刷新后进度对不上等于变相丢失

## 6. 复习与新学规则（V1.0）

### 6.1 复习（旧词）

- 算法方向：**简化 SM-2 / 间隔重复**（艾宾浩斯曲线同一类问题：到期再练）  
- 反馈：记得 / 模糊 / 忘了 → 更新间隔与 `dueAt`  
- 每日复习队列 = 当前已到期的词；展示目标约 50～75  
  - 到期 < 目标：全部复习  
  - 到期 > 上限（建议默认 75）：先刷上限，剩余留待次日或当日有余力继续（细则下一轮定）

### 6.2 新学

- 默认每日 **30** 个（后续可自定义）  
- 候选池：尚未进入学习流程的词  
- 排序权重：  
  1. 书中出现频次越高越优先  
  2. 带四级 / 六级 / 雅思标签越优先  
  3. 在加权后的结果上 **随机** 抽取当日 30 个（避免永远同一批「最顶」词，又保持优先级倾向）

### 6.3 当日流程（产品逻辑）

```text
打开今日
  → 若有到期复习：先进入复习（目标 50～75）
  → 复习告一段落（完成目标 / 到期已清 / 用户暂停）
  → 再进入新学 30
```

## 7. 词库同步（轨道 A → B）

1. HTML 为词源真源；录入后发版到站点  
2. App 识别词库版本变化并更新 WordEntry  
3. 合并时 **LearningState 必须保留**  
4. 新词进入未学池；源库移除的词：进度仍保留，列表侧处理细则下一轮定
