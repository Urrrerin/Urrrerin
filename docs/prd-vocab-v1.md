## 1. 背景与现状

### 1.1 现网 V0.5

线上：https://urrrerin.github.io/Urrrerin/

可查词表；无间隔复习、无今日队列、无可靠云端学习进度。

### 1.2 双轨

```text
轨道 A｜词库 HTML（阅读生词本，持续扩容，权威词源）
轨道 B｜Lumos App（查询 + 先复习后新学 + 进度入库）
联系：B 词表来自 A；A 更新后 B 刷新词条，学习进度必须保留
```

## 2. 产品目标

### 2.1 一句话

私人哈利波特阅读生词词典：能查；旧词按间隔重复复习；学习进度存库且不丢。

### 2.2 每日结构

1. **先复习**到期旧词（目标约 50～75）  
2. **再新学** 30 个新词  

旧词不是学一遍就过，按间隔重复到期再练。

### 2.3 V1.0 成功标准

- 先复习后新学跑通；三档反馈影响下次到期  
- 进度在数据库；换机或清缓存后仍可恢复（接入细节另议）  
- 词库扩容后旧词进度仍在  
- 每词有稳定唯一 ID

## 4. 核心概念与硬约束

| 概念 | 含义 | 约束 |
| --- | --- | --- |
| **entryOrder** | 词在 HTML 中的录入顺序（列表默认排序用） | 可随录入追加；**不是**词条身份 |
| **wordId** | 词条专属 ID | **全局唯一、稳定、不可重复**；与 entryOrder / 章内序号脱钩 |
| WordEntry | 词、音标、释义、标签、频次、章节、entryOrder、wordId… | 来自轨道 A |
| LearningState | 复习调度所需状态 | **存数据库**；**不能丢**；不对用户做前台进度页 |
| 今日队列 | 当日复习列表 + 新学列表 | 每日生成 |

### 4.1 wordId 规则（产品要求）

- 每个词条必须有专属 `wordId`，库内禁止重复  
- **不等于** HTML 表里现有的章内排序号（1、2、3…），也不等于单纯用展示顺序当 ID  
- 一旦分配，后续改释义、改排序、章节调整都 **不得更换** `wordId`  
- LearningState 只绑定 `wordId`；词库刷新靠 `wordId` 对齐，禁止因排序变化导致进度错位  
- 具体编码格式（UUID / 书册前缀+序号等）实现阶段定，但必须满足：唯一、稳定、可机器生成、可校验重复  

### 4.2 进度存储

- 学习进度 **写入数据库**（保证不因切换设备或清除缓存丢失）  
- **不需要**前台展示学习进度模块  
- 数据库选型与接入方式 **另议**；PRD 只锁定「必须持久化到库，且与 wordId 关联」

## 5. 功能需求

### 5.1 信息架构（暂定）

1. **今日** — 先复习、后新学（一次一词）  
2. **词库** — 查询 / 筛选 / 排序 / 详情  
3. **我的**（可极简）— 词库版本、必要设置；不做进度仪表盘  

### 5.2 模块需求明细

#### M1. 词库

1. **排序**  
   - **新增「默认排序」**，且 App **默认就使用该排序**  
   - 默认排序定义 = **词汇在 HTML 里的顺序** = **你的录入顺序**（`entryOrder`）  
   - 其它排序（频次、A-Z 等）保留为可选，不覆盖默认  

2. **详情页**  
   - **不需要**「认识 / 不认识」快捷操作  
   - 详情继续展示音标、释义、标签、备注等查询信息即可  

#### M2. 今日学习

- 确认交互形态：**一次一词**（卡片流）  
- 每日顺序：先复习（约 50～75）→ 再新学（30）  
- 复习反馈：记得 / 模糊 / 忘了  
- 新学抽词：高频 × 四/六级/雅思 加权后随机  
- 卡片内具体步骤/文案可继续补细（若你下一轮有要求再写）  

#### M3. 学习进度

- 进度数据：**存数据库即可**  
- **不需要前台展示**学习进度页 / 统计页  
- 进度用途：驱动复习队列与间隔计算  
- 数据库接入：另议  

#### M4. 词库同步（继承）

- HTML 更新 → 刷新 WordEntry  
- 按 `wordId` 合并；LearningState 必须保留  
- 新词分配新的唯一 `wordId` 后进入未学池  

#### M5. 设置（可后置）

- 每日新词额度自定义（默认 30）等 → 后续迭代
