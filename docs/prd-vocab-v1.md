## 1. 背景与现状

### 1.1 我们已经有什么（V0.5）

线上地址：https://urrrerin.github.io/Urrrerin/

| 能力 | 现状 |
| --- | --- |
| 词库来源 | 《阿兹卡班的囚徒》前 5 章 HTML 生词表（约 583 条） |
| 查看 | 列表、搜索、按考试标签/频次筛选、排序 |
| 详情 | 音标、释义、标签、章节备注 |

| 形态 | 手机 Safari PWA（可加到主屏幕） |
| **没有** | 新学计划、复习、已学/未学状态、打卡、跨设备同步账号 |

### 1.2 产品双轨（长期成立）

```text
轨道 A｜词库生产
  阅读哈利波特 → 遇见生词 → 录入/维护 HTML 词库
  （持续扩容，是「权威词源」）

轨道 B｜词典应用
  用轨道 A 的词库学习 → 查询 / 新学 / 复习 / 记录已学
  （功能逐步接近市面背单词 App）

联系：B 的可学词表 = A 的快照/同步结果
     A 扩容后，B 的词库要能刷新，且尽量保留用户学习进度
```

两条轨道可以由不同节奏推进：A 随时录词；B 按版本迭代功能。

## 2. 产品目标

### 2.1 愿景

为「边读哈利波特边积累英语」的个人学习者，提供一本**自己的词库驱动**的手机词典：既能查，也能按记忆规律复习，并清楚知道自己学过什么。

### 2.2 V1 成功标准（建议）

用户在通勤场景下可以完成完整闭环：

1. 打开 App，看到「今日待学 / 今日待复习」数量  
2. 完成一轮新学或复习（有对错/记得与否的反馈）  
3. 学习进度被记住，第二天打开仍在  
4. 词库后续章节录入后，新词出现在可学列表，旧词进度不丢

### 2.3 非目标（V1 明确不做）

- 多用户账号体系 / 社交 / 排行榜  
- 官方完整牛津式词典释义爬取  
- App Store 上架（继续 PWA 即可）  
- 语音评测、AI 对话练句（可放后续）  
- 安卓专项适配可作为顺带，但不单独立项

## 3. 用户与场景

### 3.1 唯一核心用户（现阶段）

本人：在读哈利波特英文，用手机碎片时间消化阅读生词。

### 3.2 关键场景

| 场景 | 描述 | V1 是否覆盖 |
| --- | --- | --- |
| S1 通勤复习 | 打开 App，按计划刷今日到期词 | ✅ 核心 |
| S2 查阅生词 | 读书时想起某个词，打开搜索确认释义 | ✅ 已有，保持 |
| S3 阅读录入 | 读完一章，把生词补进 HTML 词库 | ✅ 轨道 A（本对话录入） |
| S4 词库升级 | HTML 更新后，手机 App 词表刷新 | ✅ 必须设计 |
| S5 看自己学到哪 | 查看已学/熟悉/仍陌生的比例 | ✅ 建议有简单进度页 |
| S6 多设备同步 | iPhone + 电脑进度一致 | ❌ V1 可暂缓（见开放问题） |

## 4. 核心概念（产品词典）

必须先分清两套数据，否则复习做不下去：

| 概念 | 含义 | 谁维护 | 是否可丢 |
| --- | --- | --- | --- |
| **词条 WordEntry** | 单词、音标、释义、章节、考试标签、书中频次等 | 轨道 A（HTML→同步进 App） | 词库可更新；删词需策略 |
| **学习进度 LearningState** | 某词是否学过、熟悉度、下次复习时间、连续正确等 | 轨道 B（用户在 App 里产生） | **尽量永不因词库刷新而丢** |
| **学习队列 Session** | 今日新学列表 / 今日复习列表 | 由进度 + 计划规则生成 | 可每日重算 |

**关键原则：**  
词库刷新 = 更新 WordEntry；LearningState 用稳定 `wordId`（或规范化英文词形）对齐，能匹配则保留进度。

## 5. 功能需求

### 5.1 信息架构（建议）

底部或顶部三个主入口即可（V1 克制）：

1. **今日** — 新学 + 复习入口（主战场）  
2. **词库** — 现有列表/搜索/筛选（V0.5 能力保留）  
3. **我的** — 进度统计、每日额度设置、词库版本/刷新说明

### 5.2 模块需求明细

#### M1. 词库（继承 V0.5，小改）

- 保留：搜索、标签筛选、排序、详情  
- 增加：词条上显示学习状态徽标（未学 / 学习中 / 已掌握）  
- 详情页增加：标记「认识/不认识」的快捷操作（可选，V1.1）

#### M2. 今日学习（V1 新增 · P0）

- 展示：今日新学剩余、今日复习剩余、建议完成量  
- 新学流程（建议卡片式，一次一词）：  
  1. 先看英文（可选手动显示音标）  
  2. 用户点「显示释义」或「认识 / 不认识」  
  3. 再看中文释义与备注；确认结果写入进度  
- 复习流程：  
  1. 到期词进入队列  
  2. 用户反馈「记得 / 模糊 / 忘了」（或对错二选一，见开放问题）  
  3. 算法更新下次复习时间  

#### M3. 学习进度（V1 新增 · P0）

每个词至少记录：

- `status`: new | learning | mastered（命名可再定）  
- `easiness` / `interval` / `repetitions`（若用 SM-2 类算法）  
- `dueAt`：下次复习时间  
- `lastReviewedAt`  
- `correctStreak` 或最近反馈

全局统计：

- 总词数、已学、待复习、今日完成数  
- 简单连续学习天数（可选）

#### M4. 词库同步（V1 新增 · P0）

轨道 A 更新 HTML 后，App 需要刷新词条：

**推荐策略（写入文档供拍板）：**

1. 仓库发布新版本词库（构建进站点）  
2. App 启动时发现词库版本号变化 → 提示「词库已更新」  
3. 合并规则：  
   - 同 `id` 或同规范化 `word`：更新释义等字段，**保留 LearningState**  
   - 新词：进入词库，状态 = 未学  
   - 源库删除的词：默认保留进度但标记「已不在当前词库」（或隐藏，见开放问题）

本地「导入 HTML」可继续作为高级能力，但**主路径**应是：录入进仓库 → 发版 → 手机自动/半自动刷新。

#### M5. 设置（V1 精简 · P1）

- 每日新词上限（如 10/20/30）  
- 每日复习上限（或「不限制，清完为止」）  
- 恢复演示/清空学习进度（危险操作，需确认）

## 6. 复习算法（产品选择）

V1 不追求学术最优，追求「能坚持、好解释」。

| 方案 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| **简化 SM-2**（记得/模糊/忘了 → 间隔加倍） | 市面常见，可讲清 | 实现稍多 | **V1 推荐** |
| 固定间隔（1/2/4/7/15 天） | 极简单 | 不够因词而异 | 可做 V0.6 过渡 |
| FSRS 等现代算法 | 效果好 | 参数与解释成本高 | V2 再议 |

**推荐默认参数（可配置，先写死）：**

- 新词首次：当天或次日进入第一次复习  
- 「忘了」：间隔回到较短（如 1 天内）  
- 「模糊」：小幅延长  
- 「记得」：按 easiness 延长  
- 「已掌握」：连续高把握且间隔超过 N 天（如 30 天）可标记 mastered，降低出现频率

## 7. 版本路线图（建议）

| 版本 | 主题 | 交付 | 预估体量 |
| --- | --- | --- | --- |
| **V0.5** | 可查 | 列表/搜索/筛选/HTML（已上线） | 已完成 |
| **V0.6** | 可记 | 词条学习状态 + 手动「认识/不认识」+ 进度统计；仍可不做排程算法 | 小 |
| **V1.0** | 可复习 | 今日新学/复习队列 + 简化 SM-2 + 词库版本刷新保进度 | 中 |
| **V1.1** | 更好用 | 每日额度、连续天数、已掌握归档、错词本 | 小 |
| **V2** | 更像词典 | 例句增强、拼写练习、多设备同步、更强算法 | 大 |

**产品建议：先落地 V0.6 再 V1.0**，降低一次做完的风险；若你希望一步到位，也可直接冲 V1.0。

## 8. 轨道 A ↔ 轨道 B 协作约定

| 事项 | 约定 |
| --- | --- |
| 词库真源 | `vocab-app/public/azkaban-vocabulary.html`（及后续按书拆分的 HTML） |
| App 运行数据 | 由 HTML 生成/同步的 `WordEntry` 列表 |
| 录入工作流 | 本对话持续追加 HTML → 同步生成数据 → 发版更新 `gh-pages` |
| 学习进度 | 仅存在用户设备（V1）；发版不得覆盖进度 |
| 分支 | 功能开发用临时 `cursor/...`；稳定内容在 `master`；上线产物在 `gh-pages` |

## 9. 开放问题（需要你拍板）

下列问题不拍板，开发容易返工：

1. **一步到 V1.0，还是先 V0.6（只记状态、不排程）？**  
   - 建议：若你通勤已经很想「被安排复习」，直接 V1.0；若想先验证「标记已学」是否够用，走 V0.6。

2. **复习反馈粒度：二选一（记得/忘了）还是三档（记得/模糊/忘了）？**  
   - 建议：三档，更接近真实记忆。

3. **新学展示顺序：按章节阅读顺序，还是按书中频次，或随机？**  
   - 建议：默认「章节顺序」，可设置改为「高频优先」。

4. **多设备同步：V1 要不要？**  
   - 建议：V1 不做账号；接受进度主要在 iPhone。若必须电脑+手机同步，要提前上最简云同步（工作量明显上升）。

5. **词库刷新时，源 HTML 删掉的词怎么处理？**  
   - 建议：进度保留但列表默认隐藏，设置里可「显示已移除词条」。

6. **每日新词默认额度？**  
   - 建议：15（可改）。

7. **产品中文名是否固定为「魔法词本」？副标题是否保留书名？**

## 11. 风险与依赖

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 只存在 localStorage，清 Safari 数据会丢进度 | 高 | V1 提示备份；V2 再做导出/同步 |
| 词条 id 不稳定导致进度对不上 | 高 | 同步前冻结 id 规则；用规范化 word 作辅键 |
| 源 HTML 存在错位词条 | 中 | 轨道 A 继续校对；App 不负责「猜正确答案」 |
| 复习算法过难导致难坚持 | 中 | 额度可调；支持「今天跳过」 |
